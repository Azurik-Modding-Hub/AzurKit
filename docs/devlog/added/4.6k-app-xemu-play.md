- **The app's Play, the macOS admin attach, the tray's seed and kept build logs** (Step 4.6k, D256, D257, D261, D274; Modkit's `live_launch`, `live_helper`, its app's Play and its Build page's logs, ported): Play (the footer, beside Save) finds the player's xemu (a running one, the standard places, Spotlight, `PATH` and Flatpak, the one picked last), launches it with the saved build in its tray and a private QMP socket (the fork's shared RAM too) and tracks that build's seed with Live on, Live trying those private endpoints first (`azurkit.app.xemu`, `azurkit.app.play`, `api/play`); with the player's xemu already running it offers to attach, which on macOS reads it through the read-only root helper behind one admin prompt (`azurkit.app.live_helper`, run from a root-owned copy on macOS's own Python; `api/attach`, Attach… in the Live bar). Each Build writes a log in the user's log folder (`azurkit.app.logs`: the recipe, the report without its plan or why it failed, each save), which the Tools tab opens (`api/logs`) and Storage clears; the frozen app carries the helper as a file.
