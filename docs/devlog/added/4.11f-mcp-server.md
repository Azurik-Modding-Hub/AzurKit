- **The `azurik` MCP server** (Step 4.11f; D64, D950, D990): `devkit/mcp`, Modkit's 8 game-data tools under their names on mcp 2.3.0 and AzurKit's engine and sdk, launched by `.mcp.json` (`uv run --locked python -m devkit.mcp`), dev only. `entity_list` and `entity_get` read config.xbr (a file or an image's) by its own names with D51's spellings; `xbr_edit` writes a `.xbr` with the mods file's `set` and `replace_bytes`; `pack_list` is `sdk.catalog`'s packs with each config.xbr slider's cell; `pack_build_iso` and `rando_build_iso` build through `sdk.build` with the recipe `azurkit build` makes (the default packs, `enable`, `disable`, `params`, a mods file; a seed's settings, share and obsidian cost, a character, a spoiler file); `iso_extract` writes an image's files into a new folder whole or not at all, refusing AZ-216's names; `iso_repack` packs a folder's edits into the vanilla image with `filelist.txt` derived. Each answers in the `{success, result | error}` envelope, clamps nothing (D23), writes nothing when it fails (D35) and never over its input or a vanilla image (D36); the server keeps AZ-154's move of fd 1, so a tool's print never reaches the wire. On the same config.xbr its entity reads and `xbr_edit`'s bytes equal Modkit's tools'. `docs/MCP.md` is its reference; `tests/test_mcp.py` (3 tests) replaces Modkit's 4 files and 30 tests. mcp joins the `devkit` group, `scripts/freeze.py` leaves its cryptography out of the app, and `tests/test_contracts.py` refuses an import of mcp from `src/azurkit`. The `xemu` and `ghidra` pytest markers are registered for devkit's harness and Ghidra tests, and CI deselects `ghidra` on every leg and `xemu` on Linux and Windows (`tests.yml`, `scripts/ci_shards.py`'s log reader).
