- **The XBR file tools** (Step 4.6l; D950, Modkit's `azurik-mod xbr` verbs, P62 and P63): `python -m devkit xbr` holds `inspect` (a TOC entry's first records, each 4-byte column labelled by the first reading that fits, the stride detected; a column's bytes only with `--hex`), `diff` (each tag's size change, the strings each tag gained or lost and each entry changed in place; exit 1 when the files differ), `edit` (strings, bytes and keyed cells into a new file, whole or not at all, never over its input or a vanilla image), `xref` (the pointer fields AzurKit's parse models: config.xbr's 18 keyed tables, 10,340, with the damage and magic tables Modkit's model left out, and the unmodeled sections) and `verify` (the file parses whole; `--cross-check-schema` lists a pack's config.xbr cell `schema.json` doesn't document), on `core.xbr`. Modkit's refusing-only `--add-row`, `--remove-row` and `--grow-pool` aren't ported. `devkit/xbr/README.md` is the reference, `tests/test_devkit_xbr.py` the tests (Modkit's xbr CLI and schema-lint tests, merged into five).
