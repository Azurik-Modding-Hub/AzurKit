- The store (Step 4.3r, D1015): `src/azurkit/store.py` keeps what AzurKit works out between calls and launches in one folder a kind (`store.KINDS`: plans, layers, dresses, pictures, memos, swap), JSON or AZKP1 and never a pickle (`swap` keeps the bytes `characters._kept` and `engine._kept` still pickle, until they move to `dresses` and `memos`/`pictures`), each entry sealed whole (its kind, key, length and body: a sha256, the app's an HMAC under `cache.key`) so a torn, altered or moved entry is a miss, never decoded; one budget of 5 GiB across the kinds, the least recently used out first whatever its kind, and only files of its own names in its own folders ever removed (a player's settings, content installs and key never). It starts no thread, so the page's worker can run it. The app's `swapcache` sits on it (`Kept`; the swap's own 2 GiB is now the one budget): every put is written behind the answer by one daemon writer thread a process (a get meanwhile answers from what it holds; a quit never waits on it, and a write it cuts short leaves only a part file), and 4.3i's `swap/*.pickle` files are never read and are removed by the next write.
