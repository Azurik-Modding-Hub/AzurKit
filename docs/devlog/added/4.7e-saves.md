- Saves' engine (Step 4.7e, D919's save editor; the Saves section and `azurkit save` come with its hub half): `azurkit.tools.saves` reads a slot from its folder or every Azurik slot on an xemu HDD image (a qcow2, versions 2 and 3, or a raw disk; its E: drive's FATX, read-only), decodes each file (the container's fields, a text save's lines, a binary save's version and named word, the signature), changes a text save's lines all or none, signs the slot again with the console's key, derived in memory from the player's own flash image and MCPX boot ROM over the game XBE's title key (AzurKit holds only the certificate key's fingerprint), and writes it as a new folder or a zip whose bytes are the same on every call. The reader keeps SEC-12's checks: a visited set and a chain capped at the volume's clusters, a folder read once and at most 4,096 records, the header's fields checked against the file's size, a compressed cluster, a backing file and an encrypted image refused by name, and every name a save holds checked once (no separator, `..`, NUL, control or device name), so a zip's entries are the slot's own names. On the D98 oracle drive it reads the one slot in 7 block reads, and the game's own signature checks under the derived key. The hub half (Step 4.3r4q): `sdk.saves` (`tools/saves/session.py`), the Tools tab's Saves on both hosts (`web/saves.mjs`, `api/saves`), `azurkit save inspect|edit`; the independence contract holds five tools.
