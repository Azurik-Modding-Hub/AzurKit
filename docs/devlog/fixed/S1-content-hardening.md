- A PNG is inflated with bounds (`core/inflate.py`): one past 4096x4096 is refused before a byte inflates, and image data longer than its header's rows (a zlib bomb: 64 MiB of file to about 66 GB) is refused after at most one byte more, in the textures' reader and in a glTF folder's read-back (Step S1, D992 SEC-5).
- A content manifest is checked in time linear in its size: its requires are walked once with a done set and a stack of its own, so an 80-entry lattice that took months is checked at once and a 5,000-deep chain is named, not a `RecursionError`; a manifest holds at most 1,000 entries and 10,000 files, a JSON nested too deep or a requires that isn't a list of ids is refused by name (Step S1, D992 SEC-6).
- An Install checks each file as it lands and writes it into the entry's `.part-<id>/` folder, so it holds one file at a time (4 files of 5 MiB: 5.4 MB held, from 21 MB), and a refused file removes the parts and writes nothing; an entry's files, and an Install's (the entry and those it requires), are at most 256 MiB (Step S1, D992 SEC-9; the hosts' fetch reading at most a file's size is 4.3m's).
- An Update removes only the paths `installed.json` lists that are content paths, so a hand-edited record naming `../` or an absolute path never deletes a file outside the content folder; a content path with a `:` (a drive or an NTFS stream) or a name Windows keeps for a device (`CON`, `NUL.json`, `COM1`) is refused, and two entries' paths that differ only in letter case are one file, as the content repository's check holds (Step S1, D992 SEC-15).
- A content file's suffix is one its folder takes (`content.SUFFIXES`): a variant's recipe and the files read beside it (`.json`, `.glb`, `.gltf`, `.bin`, `.png`), clips (`.glb`, `.gltf`, `.bin`), sounds (`.wav`), effects (`.glb`, `.gltf`, `.bin`, `.png`), a pack's `.json`, and a `.md` note in each; any other, such as `.html`, `.svg` or `.js`, is refused by name at Install and on the site, as the content repository's check refuses it (Step S1, D992 SEC-3's allow-list).
- A recipe's file fields (a glTF clip's `file`, a mesh's `gltf.file`, a colours or effects picture's and an effect mesh's `file`) are files in the recipe's folder: a `..` part, an absolute path, a `\`, a `:` or a NUL is refused by name when the recipe is read, so a recipe someone hands you reads nothing outside its folder, and a clip file's sha256 mismatch names its first 12 digits (Step S1, D992 SEC-14).
- A lint test keeps the page free of HTML sinks: no file under `web/` sets `innerHTML` or `outerHTML`, calls `insertAdjacentHTML`, `document.write`, `createContextualFragment` or `parseFromString`, or holds a `srcdoc` or a `javascript:` URL, so no text from a manifest, recipe or mods file becomes markup on the site's origin (Step S1, D992 SEC-18).
