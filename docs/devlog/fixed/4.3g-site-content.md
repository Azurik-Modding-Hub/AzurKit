- **The site publishes only checked content** (Step 4.3g; D992, SEC-3): `scripts/web_tools.py --site DIR --content CLONE` checks the clone before it writes the site's first file (`web_tools.content_files`): the manifest passes `content.check` and each entry `content.verify` (size, sha256, no disc image, a built-in's recipe), as an Install does; each listed path is a plain path (a trailing `/` or a `.` part is refused, so what is checked is what is published), has no `:` and is a regular file reached through real folders (`lstat`: no link is followed, so a listed link or a linked folder can't publish the deployer's files); its suffix is one of an allow-list, the kinds the content repository holds or is to hold: `.bin`, `.glb`, `.gltf`, `.json`, `.md`, `.png` or `.wav` (any other suffix, or none, is refused by name, so no page, script or XML document the browser renders, `.html`, `.svg`, `.js`, `.xml` or `.xsd` among them, reaches the site's origin); and each destination resolves inside `content-source/`. A fault names the file and writes nothing. It writes the bytes it checked, not a second copy of the clone's files.
