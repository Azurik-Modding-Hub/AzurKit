- **The site publishes only checked content** (Step 4.3g; D992, SEC-3): `scripts/web_tools.py --site DIR --content CLONE` checks the clone before it writes the site's first file (`web_tools.content_files`): the manifest passes `content.check` and each entry `content.verify` (size, sha256, no disc image, a built-in's recipe), as an Install does; each listed path has no `:` and is a regular file reached through real folders (`lstat`: no link is followed, so a listed link or a linked folder can't publish the deployer's files); none ends in `.html`, `.htm`, `.xhtml`, `.svg`, `.js`, `.mjs` or `.xml`, which the host would serve as a page or a script on the site's origin; and each destination resolves inside `content-source/`. A fault names the file and writes nothing. It writes the bytes it checked, not a second copy of the clone's files.
