- **A save edit never writes the new slot inside the one it read** (Step 4.28g; Modkit's AZ-141): `azurkit save edit SLOT --out SLOT/out`, or the app's Save into a folder inside the slot it opened, wrote the new slot there, a folder the game's signature then covered, so the original no longer loaded. The Saves session keeps the folder each slot was opened from and refuses an output inside it by name, and the CLI opens a slot's folder through it. Modkit's other save edges are pinned with it: a non-ASCII SaveMeta name, a text part ending in loc.sav's binary tail with no newline (AZ-339) and 8-bit text (H9) round-trip, a .sav under 8 B is a file, a signature.sav not of 20 B no signature, a key not of 16 B is refused, a folder named like a save stays a folder (L25), a slot signed with no edit is signed as it is (Step 2.84), and each bad `save edit` input is one line, exit 1, nothing written.
