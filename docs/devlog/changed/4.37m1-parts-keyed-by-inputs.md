- **A Check's parts are kept under their stages' inputs alone** (Step 4.37m1, D1195): every part's key is the code's version (`parts.VERSION`, the digest of what a dress runs), the recipe fields and files its stage reads, the keys of the parts before it and the layout of the file it is pages over, never a digest or pickle of a file an earlier stage wrote or a float the dress worked out; the files between two parts are named by the last part's key and what the glue reads (DRESS: never the recipe's sounds, which only their own stage reads, so a sound edit still takes every part). So the parts the recording host ships serve every computer and the site alike, a Check's answer there close enough to its own fresh dress. `shipped.json` names the version its rows were recorded at (`keys`), and a table of another version gives no part.
